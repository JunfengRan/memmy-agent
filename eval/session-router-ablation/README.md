# 会话归属消融：基线 / Jev / Super Agent / Jev + Super Agent

日期 2026-11-09。分支 `feat/superagent-session-router`。脚本和原始输出的原位置在 `feat/superagent-session-router` 分支的 worktree（`.worktrees/superagent-session-router/eval/session-router/`）。本目录是为方便查看放入的副本：`results/` 是每次运行的预测和分数（`<格子>-r<次>.json`）、`summary.json` 汇总和 `dataset.json` 输入，`run-ablation.ts` 与 `jev-topic-choice.ts` 是脚本副本。脚本依赖那个分支上的 `App/memmy-agent/src/core/session/superagent-session-router.ts`，在本分支不能直接运行。

## 实验设定

任务和数据集沿用 Super Agent 实验：23 条消息（6 个 Cursor 会话按轮转交错，`runs/dataset.json`），路由器逐条决定它属于哪个会话。金标是消息来自哪个原始会话，同一会话的不同条目不一定是同一件事。

两个因子加一个基线：

| 格子 | 协议 | 模型 |
| --- | --- | --- |
| baseline | 词法：与已有会话卡的 token 重叠大于 0 就并入，否则新建（与 Jev 评测的词法对照同一规则） | 无 |
| Jev | 类型化选择题（`decisions/topic-choice.ts` 的 add 题，候选是会话卡，选项含 `new` / `none`） | gpt-6-luna |
| Super Agent | accept / attach / ignore / stop 路由（`superagent-session-router.ts`，prompt `2026-11-06.1`） | DeepSeek（原 Super Agent 实验用的模型） |
| Jev + Super Agent | 同上的 Super Agent 路由 | gpt-6-luna |
| （补充）Jev 协议 + DeepSeek | Jev 选择题 | DeepSeek |

「Jev + Super Agent」指用 Jev 的决策模型跑 Super Agent 的路由协议。补充格子把模型和协议拆开，用来看提升来自哪一边。

每个模型格子独立跑 3 次，表中是均值（最小–最大）。基线确定性，只跑 1 次。会话卡规则：Jev 协议的卡是标题（取首条消息前 80 字）、最近一问和最近一答；Super Agent 协议沿用原卡片。gpt-6-luna 不接受 `temperature: 0`，没有传；DeepSeek 为温度 0。

## 指标

指标都由脚本从预测算出，不靠人工判分。

- **会话纯度**（lenient accuracy）：消息进了某个会话，且该会话里没有来自别的原始会话的消息，才算对。被忽略或被拒绝算错。
- **attach 精确率**：所有 attach 里，被附着的会话此前只含同一原始会话的消息的比例。
- **续接命中率**：同一原始会话已有前文的 17 条消息里，被附着到纯净同源会话的比例。
- **B-cubed P / R / F1**：被忽略或拒绝的消息各算一个单独的簇。
- **跨项目合并**：同时含两个项目消息的会话个数。

### 指标算例

用一个 6 条消息的小例子手算一遍（例子是编的，真实数据是 23 条，算法相同）。金标是消息来自哪个原始会话：A 是 MemOS，B 是 Clash，C 是 Hy-Memory。

| 消息 | m1 | m2 | m3 | m4 | m5 | m6 |
| --- | --- | --- | --- | --- | --- | --- |
| 金标 | A | B | C | A | B | C |
| 路由器的决定 | 新建 s1 | 新建 s2 | 新建 s3 | 附着 s1 | 附着 s1（错） | 忽略 |

结果：s1 = {m1(A), m4(A), m5(B)}，s2 = {m2(B)}，s3 = {m3(C)}，m6 不在任何会话里。

- **会话纯度**：消息进了某个会话，且该会话里没有别的原始会话的消息，才算对。m1、m4、m5 所在的 s1 混了 A 和 B，算错；m2、m3 在纯净会话里，算对；m6 被忽略，算错。纯度 = 2/6 = 0.333。
- **attach 精确率**：只看附着动作，检查目标会话此前的成员是否全部同源。m4 附着 s1，此前只有 m1(A)，对；m5 附着 s1，此前是 A、A，而它是 B，错。精确率 = 1/2。新建和忽略不计入。
- **续接命中率**：只看前面已出现过同一原始会话的消息，这里是 m4、m5、m6 共 3 条。m4 附着到只含 A 的前文，命中；m5 附着的会话里全是 A，没命中；m6 被忽略，没命中。命中率 = 1/3。
- **B³ P / R / F1**：每条消息单独算再平均，被忽略的消息各算一个单独的簇。单条 P = 所在簇里同源消息数 ÷ 簇大小，单条 R = 所在簇里同源消息数 ÷ 该原始会话总条数。

  | 消息 | 所在簇 | P | R |
  | --- | --- | --- | --- |
  | m1 | s1（A、A、B） | 2/3 | 2/2 |
  | m4 | s1 | 2/3 | 2/2 |
  | m5 | s1 | 1/3 | 1/2 |
  | m2 | s2 | 1 | 1/2 |
  | m3 | s3 | 1 | 1/2 |
  | m6 | 单独一个簇 | 1 | 1/2 |

  P = (2/3+2/3+1/3+1+1+1)/6 = 0.778，R = (1+1+0.5+0.5+0.5+0.5)/6 = 0.667，F1 = 2PR/(P+R) = 0.718。
- **跨项目合并**：同时含两个项目消息的会话个数，这里 s1 含 A 和 B，所以是 1。
- **被丢弃**：被忽略或被拒绝的消息数，这里是 1。**会话数**：形成的会话个数，这里是 3。

怎么读：

- 精确率类（纯度、attach 精确率、B³ P）问「并进去的对不对」，Super Agent 不确定就新建，所以最高。
- 召回类（续接命中率、B³ R）问「该并的并了没有」，Super Agent 拆得碎所以偏低；Jev 召回高是靠把很多消息并成大会话换来的。
- B³ F1 折中两边：全并成一个会话，召回是 1、精确率很低；每条各开会话，精确率是 1、召回很低。所以四个方法的 F1 差不多，区分不了，要看纯度和跨项目合并。
- 金标是原始会话，而同一会话里可能有互不相关的请求，所以续接命中率偏严：Super Agent 把「相似但是新请求」另开会话，也记为没命中。

## 结果

| 方法 | 会话纯度 | attach 精确率 | 续接命中率 | B³ P | B³ R | B³ F1 | 跨项目合并 | 被丢弃 | 会话数 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| baseline（词法） | 0.043 | 0.000 | 0.000 | 0.206 | 0.935 | 0.337 | 1.0 | 0 | 2 |
| Jev | 0.246 (0.17–0.39) | 0.333 (0.29–0.41) | 0.333 (0.29–0.41) | 0.584 | 0.667 | 0.622 (0.60–0.67) | 2.7 (2–3) | 1.7 (1–2) | 4.3 |
| Super Agent | **0.986** (0.96–1.00) | **1.000** | 0.392 (0.35–0.47) | **1.000** | 0.457 | 0.626 (0.59–0.67) | **0** | 0.3 (0–1) | 16.0 |
| Jev + Super Agent | 0.899 (0.87–0.91) | 0.880 (0.86–0.91) | 0.451 (0.35–0.59) | 0.952 | 0.495 | 0.649 (0.58–0.73) | 1.0 | 0 | 14.3 |
| （补充）Jev 协议 + DeepSeek | 0.391 (0.26–0.52) | 0.509 (0.40–0.59) | 0.451 (0.35–0.59) | 0.709 | 0.638 | 0.669 (0.60–0.73) | 2.3 (2–3) | 2.0 (0–4) | 6.0 |

## 结论

1. **三种方法都明显好于词法基线。** 基线几乎把所有消息并进一个会话（会话纯度 0.04）。
2. **Super Agent 的协议是纯度的来源，不是模型。** 它的 attach 精确率 1.000、没有跨项目合并。换成 gpt-6-luna 后仍有 0.88 和每轮 1 个混项目会话（第 1 轮是 Hy-Memory 的一条被并进 MemOS 的会话）。Jev 的选择题协议无论用哪个模型，纯度都只有 0.25–0.39，并且每轮出现 2–3 个混项目会话。
3. **Jev 选择题的问题在于「倾向并入」和「会丢请求」。** 选项里只有已有会话、`new`、`none`，没有「要指向这个会话才能附着」的约束，所以只形成 4–6 个会话，把不同项目的消息吸到一起。`none` 还会丢掉完整请求：Jev 每轮都丢掉 t04（Codex 连接失败）。
4. **Super Agent 偏保守。** 续接命中率只有 0.39，会话数 16，远多于 6 个原始会话。原因是它把「主题相似」当成新请求，这符合它的设计，但也说明它拆得过碎，B³ 召回只有 0.46。
5. **B³ F1 在四个模型格子几乎一样（0.62–0.67），区分不了它们。** 这是金标按原始会话划分造成的：一个会话里本来就有互不相关的请求，合并得多的 Jev 在召回上占便宜，保守的 Super Agent 在精确率上占便宜。看跨项目合并和纯度更合适。
6. **Jev + Super Agent 没有超过单独的 Super Agent。** 纯度 0.90 对 0.99，差距大于单格子 3 次的波动范围；续接命中率 0.45 对 0.39，在波动范围内，不能说更好。在这个任务上 gpt-6-luna 换掉 DeepSeek 没有带来收益，反而引入了混项目合并。

## 局限

- 数据只有 23 条、6 个会话，每格 3 次，差距小的指标（续接命中率、B³ F1）在噪声内。
- 金标是原始会话，不是人标的「同一件事」。续接命中率会把「同一会话里的新请求不并入旧会话」记为未命中，所以它偏严；Super Agent 之前人工判的 0.913 用的是更宽的规则，不能与本表的会话纯度直接比。
- 这是会话归属任务，不是 Jev 原评测（主题卡上的 add 归属与 search 选题，见 `docs/project-memory/metrics.md` R-20261106-01）。那组实验里 Jev 的 add 归属准确率是 0.882，两个数字衡量的对象不同，不要互相对比。
- Jev 协议的 `new` 没有标题，会话标题用首条消息前 80 字代替；`jev-topic-choice.ts` 是 `Memory/src/service/project-memory/decisions/topic-choice.ts` 的副本（该文件不在本分支上）。
- 没有测 Super Agent 的 `stop`：数据集里没有停止类消息。
