01结论与边界

这是一份可重放的项目记忆检索基线。语料有两个隔离项目（ledger、catalog）、34 条带时间的对话轨迹、30 个 relay 问题，以及决策、冲突、todolist 和评分规则。每个问题都落在下面五条时间线中的一条，并明确询问“谁的什么状态”。

复核边界

reviewed gold 的抽取过程是 mock add_message：不调用线上写入接口，不重新手写问题答案；脚本读取复制后的 corpus、decisions、relay，按规则重建金标。Local 的 project add/search 已实现真实模型回放，真实结果单独记录在 generated/live-report.json，不覆盖金标。

02数据集总览

输入文件保留 alpha 的证据合同：corpus.json 是事实语料，relay.json 是问题和 gold rubric，decisions.json 是旧抽取结果，conflicts.json、todolists.json 与 scheme.json 用于写入链路和边界检查。复制后运行 build-sessions.mjs 生成项目会话文件，避免手写回放记录。

04Memmy 中的评测方法

回放流程

  1. 在隔离 SQLite 中加载 dataset/corpus.json，按项目会话分组保留 trace 的 query、answer、chat_time 和 source_trace_id。
  2. 按时间顺序调用 Local 的 POST /api/v1/memory/add，传 user_id、space_ids、allow_memory_view:["project"] 和原始 messages；由已配置的 summary 模型抽取 decision、experience、evolution。
  3. 对每个 relay 问题调用 POST /api/v1/memory/search，传题目的 space_ids / domains；服务先做空间与领域硬过滤，再按词法证据排序，并可由同一模型生成 answer。
  4. 记录返回的 topic、条目类型、source trace、项目范围、rank、延迟和 token；使用 mustInclude / mustNotInclude 计算最终回答准确率。
真实回放结果

当前配置的 claude-haiku-5-5 回放写入 25 条模型条目；add 严格 topic 对齐 F1=0，search evidence recall=0.871、trap rate=0.704、scope leak=0，最终回答准确率=0.300、trap rate=0。结果文件为 generated/live-report.json；同一配置重复运行会有模型输出和排序波动。

最低可复现评分

hit(q, a) = all(phrase in a for phrase in q.mustInclude)
trap(q, a) = any(phrase in a for phrase in q.mustNotInclude)
score(q, a) = 1 if hit(q, a) and not trap(q, a) else 0
Recall@K = mean(score(q, topK_context_answer))
TrapRate = mean(trap(q, answer))
ScopeLeakRate = wrong_project_or_project_memory_in_global_window / scope_leak_questions

每次运行至少报告总体分数、按 kind 的分数、scope-leak、stale 误召回、cross-project 误召回、P50/P95 延迟和每题证据。空回答必须得 0；goldAnswer 必须得满分。建议同一配置重复 3 次，报告均值和范围，避免把单次模型波动当成 Search 改进。
