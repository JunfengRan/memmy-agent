项目记忆把改口之后的事实留下来了

01摘要

这轮预研要回答的问题很具体：两个仓库、多名 Agent 先后改口之后，已经写进记忆的内容，还能不能答出现在有效的事实。我们没有去模拟两个互相搜不到的 Cursor 窗口。要看的是记忆本身。

语料是 ledger 和 catalog 两个小仓库上的 34 条工作记录，按时间回放。每问一题，库里只有这题之前的记录。题一共 30 道，q21 的题面本身有问题，不进统计，分母是 29。题分成五类：跨项目 11 题，过时 9 题，被后来的说法改口 5 题，普通事实 3 题，以及 1 题没打开项目目录、不该拿到项目代码的作用域串扰。

三种做法对照着跑。空白对照是现在的 Memmy 召回。项目记忆在写入时记下项目、现行结论、检查点和事项，并把被改口的旧记录标成已被取代。属性树不改写入，只在读的时候把记忆收成一棵按文件组织的树，贴在原来的召回前面。属性树用的是第 3 轮，粒度到文件，注入预算 1400 字。

直接检查召回文本里有没有现行要点、有没有把陷阱说成现行：项目记忆 22/29，空白对照 10/29，属性树 11/29。被改口的 5 题，项目记忆 5 题都过了，另外两列都是 1 题。过时的 9 题，三列分别是 6、3、3。属性树和空白对照几乎贴在一起。

再让模型只根据这段召回作答，由同一个裁判打分：项目记忆 23/29，空白对照 19/29，属性树 16/29。空白对照从召回的 10/29 升到回答的 19/29，说明很多题不是完全没召回，而是新旧说法都在上下文里，模型还能选。项目记忆的回答只比召回多对 1 题，说明它的上下文已经比较干净，模型没有多少额外空间。属性树的回答是 16/29，低于空白对照的 19/29。多出来的树文本没有帮模型做选择。

Cursor 只完成了项目记忆这一列。作答模型只看到该题的项目记忆上下文，不能读仓库。裁判结果 18/29，低于同一上下文上的 Memmy 模型回答 23/29。空白对照和属性树的 Cursor 回答这轮没有采，表上写待验证，不能外推成 Cursor 全面高或全面低。

证据合同

问题是三种做法在这 29 题上差在哪里，差是从哪一类题来的。读者是要决定预研下一步的人。不覆盖产品界面，也不把没采到的两列 Cursor 写成已完成。数字来自 runs/*-recall.json、runs/*-answer.json 和 runs/cursor-answer-project.json。材料里没有的判断标成待验证。

02问题

项目上的记忆和单人备忘录不一样。同一个仓库里，后面的决定会改掉前面的做法；旁边还有另一个仓库，里面的句子用词很像，却不能拿来回答这个问题。Agent 换一扇窗口继续干的时候，需要的是现行事实，连同它属于哪个项目。

只把历史对话全部召回，会碰到两种失败。一种是新旧都在，回答的人挑了旧的。一种是召回是空的，回答的人只能说不知道，或者离开记忆去翻仓库。还有一种更窄：当前窗口根本没打开项目目录，却把别的项目的月报算法讲了出来。

所以评测做成三类结果，每类三种方式。

结果在量什么
直接召回上下文里必须出现每一条现行要点，并且不能把陷阱说法当成现行事实。陷阱也出现在上下文里，这题就是失败，即使要点也在。
模型回答模型只能看这段记忆。裁判看回答有没有体现现行要点，有没有把陷阱当成现行事实，并给一个错因。
Cursor 回答另一个作答模型只看该题上下文，不使用工具、不读仓库。裁判和上一行是同一套。

直接召回更严。它衡量的是注入文本干不干净。模型回答衡量的是一个会阅读的模型能不能从混杂的文本里选出现行事实。两行数字可以差很多，这是评分定义造成的，两行都要看。

空白对照的代码基线是 8684cb570f1b54debcdd45da45f0f02661a76a42。评测时有一处历史过滤两边都改过：问题里一出现「价格」，旧逻辑会把整层轨迹记忆丢掉，catalog 的题就会全部变空。这个过滤收窄之后，两边才是在比项目记忆，而不是比谁先被这条旧规则挡住。因此空白对照是「原始 Memmy 加上这一处过滤修正」，写报告时按这个范围理解。

03算法

空白对照

空白对照走原始 Memmy 的写入和召回。一条工作记录进来，做成轨迹记忆，带摘要和向量。提问时按相关性把历史证据注入上下文。它没有「这是哪个项目的现行结论」这一层，也没有把后来说的话标成对前一句话的取代。

项目记忆

项目按 git 仓库根来认。同一个仓库里的子目录共用一个项目身份，另一个仓库是另一个项目。召回之后按作用域乘一个系数，系数写在 Memory/src/service/project/scope-weight.ts。

记忆落在哪里系数
同一项目的轨迹记忆1.0
同一项目的上层记忆1.3
全局轨迹记忆0.5
其他项目的轨迹记忆和事项不进入候选
其他项目的策略0.4
已被标成取代的记录不进入候选

写入侧多了三块给当前窗口看的文字：现行结论、检查点、事项。检查点来自这一轮待办从进行中到完成的边界。一项决定如果后来改过口，后一条写成现行结论，前一条标上已被谁取代。冲突里赢的那一边同样处理。提问时，这些句子排在「其他 Agent 最近做了什么」之前。空白对照看不到这三块。

这一支要解决的是「哪句还算数」。作用域系数解决串到另一个仓库，现行结论和取代标记解决同一仓库里的改口。

属性树

属性树是读时实验，写在原始 Memmy 上，代码在属性树工作区的 eval/attribute-tree.mjs。它不改库里的记忆。提问时先把当时库里的记忆收成记录，按项目、文件和种类归行，再按本轮的粒度截断，拼到原召回的前面。

三轮只改注入的粒度和字数。第 1 轮按项目，280 字。第 2 轮按模块，700 字。第 3 轮按文件，并带上上级，1400 字。本报告的属性树列是第 3 轮。选择范围是当前项目加上全局记录。其他项目的记录不进这棵树。

它要解决的是上下文太长、两个项目混在一起。它不单独写一句「现在以哪边为准」。树里的一行仍然是原来的记忆文本。实际注入里还能看到摘要和原始轮次缠在一起，所以读到的是一层索引，决定句还是旧文本。

04实验

回放按时间排序。每条工作记录入库之后，把摘要和向量的队列排空，再问这段时间里的题。不排空的话，召回只剩关键词，三列会看起来一样。作答和裁判用的模型是 claude-haiku-5-5。Cursor 作答是另一路，只接收该题的记忆文本。温度参数不传，这个模型的接口不接受它。

q21 问的是 catalog 价格列现在怎么读金额。题面里同时有「价格」和「现在」，裁判多次被接口过载打断，题本身也和前后的金额题缠在一起。这道题留在数据里，不进任何一列的分子和分母。

空白对照和属性树的 Cursor 回答没有采集。缺的是用这两列各自的召回文本、按同样的「只看记忆、不读仓库」约束再答一遍。在这两份原文出现之前，不能比较 Cursor 在三种做法上的差别。

05结论

项目记忆相对空白对照多对的题，落在改口、过时和跨项目。被改口的 5 题，召回是 5/5 对 1/5。过时的 9 题，召回是 6/9 对 3/9。跨项目从 4/11 到 8/11。普通题项目记忆是 3/3，空白对照是 2/3。

这个分布和算法对得上。现行结论把「现在以哪句为准」写在上下文最前面，取代标记让旧句退出候选。空白对照把前后两次说法都留下来，字符串评分一看到旧句就算失败。模型阅读之后，空白对照能从 10/29 补到 19/29，补上的正是那些新旧都在、人还能选的题。项目记忆的模型回答 23/29，只比自己的召回多 1 题。上下文已经把现行句放对了位置，模型再选一次，空间很小。

属性树没有形成独立收益。召回 11/29，只比空白对照多对 1 道普通题。过时和被改口都停在 3/9 和 1/5，和空白对照相同。模型回答 16/29，低于空白对照的 19/29。跨项目的模型回答是 5/11，空白对照是 8/11。树把更多原文贴回提示词，模型更常说「记忆里没有」，空召回从空白对照回答里的 5 题变成属性树的 9 题。读时索引没有代替「哪句是现行」。

还有一道题三列都没过，而且不该被讲成小问题。q20 的窗口没有打开项目目录，金标是这里没有月报代码。三列的召回都失败，三列的模型也都把 ledger 的月报算法讲了出来。项目记忆这一题的上下文里甚至没有「现行结论」那一段，送进去的是普通召回。作用域权重还没有挡住「当前没有项目」这一种窗口。

Cursor 在项目记忆上下文上是 18/29。它低于同一上下文的模型回答 23/29。差出来的题里，有的是漏了要点，有的是把已经撤回的文件说成还留着，也有一道是意思对了、原词没对齐。下一节把错因拆开，避免把 18/29 读成 Cursor 不会用这段记忆。

06错因

错因只存在于模型裁判。直接召回没有这一个字段。裁判在答错时五选一：召回空或答不出；把过时说法当成现行；几条相似信息没有选；用了另一个项目的说法；其余归入其他。答对记成答对。下面每张饼图的分母都是 29，一块是这一类的题数。

模型回答

空白对照答对 19/29。错题里最多的是答不出：上下文里没有现行句，模型明确说不知道。另有把过时说法当现行、没在相似句里做选择、用了另一个项目，以及归入其他的题。这张图说明空白对照的主要问题是现行事实没有被单独留下，旧事实还占着上下文。

项目记忆答对 23/29。错题少，而且几乎都是答不出：精度、时区、output 目录、样例文件这几件，现行句没有进到这一题的上下文里。另有 1 题把不该讲的月报算法讲成了现行事实，就是上面的 q20。项目记忆的错因图里，过时和串项目都不再是主要块。

属性树答对 16/29。答不出是最大的一块，比空白对照更多。过时和没选清楚各留下 2 题。这张图和总分一致：树没有把空召回补上，也没有消掉改口。

Cursor

项目记忆的 Cursor 回答答对 18/29。错因和上面用的是同一套裁判、同一批要点。空白对照和属性树没有这张图，因为原文没采。

Cursor 的「其他」比 Memmy 模型回答多。抽查之后，这里面不都是事实反了。q11 问没有清单的那一轮要不要拆开，Cursor 写了「不要拆开，整段做完」，金标要点是「没有拆开」。意思对齐了，裁判因为原词不一样判了其他。q29 的保存回答是「按 id 去重，只留最早那条」，裁判理由却写成没有看到回答。这一题的错因标签不可靠，总分仍按文件里的 18/29 报告，不在这里手工改分。其余错题里，q16 把已经撤回的 month.json 说成还留着，q05、q08、q26 和模型回答一样，是上下文里没有精度、目录和时区。

07样例

下面每题都给出问句、现行要点，以及三列里能说明机制的回答。引用截到能核对的长度，全文在附录的错题表和结果文件里。

改口：分支

q19 问改动应该放在哪个分支上。现行要点是 main 不直接改。金标是先放 feature 分支。这题在直接召回上，项目记忆通过，空白对照和属性树都不通过。模型回答同样只有项目记忆通过。

空白对照的回答是：记忆里没有关于分支的信息，所以无法确定。它记得的是空客户行怎么跳、样例文件已撤回、改动留在当前窗口。这些都是真的旧记录，里面没有后来那句「放 feature，main 不直接改」。项目记忆的回答是：改动放在 feature 分支上，不直接修改 main。现行结论把后一句放到了上下文前面。

过时：还搬不搬

q09 问 catalog 的导出做法有没有抄进 ledger，后面还搬不搬。现行要点是月报用不上 export。陷阱是「再看要不要搬」。金标是拷贝已经撤掉，dry-run 之后不再搬。

空白对照回答说拷贝后来撤掉了，后面搬不搬还没定，要等 dry-run 再决定。撤掉这件事它记得，旧的「再看」也还在，模型选了旧的那半句。项目记忆回答说没有抄进去，月报用不上这份导出。这是现行结论在起作用，模型少选了一次。

跨项目：为什么改成读一列

q25 问月报后来为什么改成直接读 entries 的一列。现行要点是扫全文太慢。陷阱是把 catalog 的理由「价格查询太慢」拿过来。

空白对照回答说记忆里没有这件事，现有记录是相反的：entries 的表结构没改，金额仍在 journal 正文里。它停在更早的那次决定上。项目记忆回答说原来扫整个 journal 太慢，加上 amount 列之后直接读这一列。两个仓库的「加一列」没有被说成同一件事。

召回空了之后模型会离开记忆

q14 问 README 里现在还有没有数据库连接串。现行要点是已经删掉了。空白对照这一题的召回是空的，模型回答写「记忆部分是空的，我直接查仓库里的 README」。这违反了只根据记忆作答的约束，也说明空召回在真实使用里会变成去翻工作区。项目记忆回答连接串已经删了，密码只留在本机的 .env。属性树这一题的模型回答也通过了，召回文本本身仍是失败：字符串评分看到陷阱句还在上下文里。

三列都没挡住的窗口

q20 问 ledger 的月报现在怎么汇总金额，但这个提问窗口没有打开项目目录。现行要点是没有月报代码。陷阱是把「不再扫描 journal 全文」讲成这个窗口里的现行事实。

三列召回都失败。空白对照的模型把 entries 的 amount 列、空客户规则和东八区月份都讲了一遍。项目记忆的模型同样讲了直接读 amount 列、整数分和按 id 去重。Cursor 在这一题上也讲了 report.ts 里的去重和 amount 列。三路都把别的会话里的月报事实，答成了这个没打开目录的窗口的现状。这是目前最清楚的产品缺口：没有项目的窗口，仍然收到了项目记忆。

Cursor 把撤回说成还留着

q16 问 tests/fixtures/month.json 还留不留着之前的改动。现行要点是 month.json 已撤回。项目记忆的模型回答说记忆里没有这个文件，属于答不出。Cursor 的回答是「还留着。样例文件仍然有效」。同一段上下文，一个模型承认没有看见，一个模型把旧状态说成了现在。Cursor 这一列的风险在于会把上下文里的旧句说得更肯定。

08总结

这轮数据支持把项目记忆继续做下去，支持的是其中「现行结论」和「被改口的旧记录退出候选」这两件事。它们把被改口的题从 1/5 做成了 5/5，把过时题从 3/9 做成了 6/9，并把直接召回从 10/29 做成了 22/29。作用域系数对跨项目有帮助，召回从 4/11 到 8/11，但没打开目录的那一道仍然失败。

属性树这一轮不能当作独立方案往后推。它的召回 11/29，模型回答 16/29，都没有超过空白对照。读的时候多贴一棵树，没有产生「现在以哪句为准」。若以后还要试注入形态，应该先让注入的是一句决定，再谈文件粒度。

给下一步的顺序也很清楚。先修没有项目目录的窗口，让它不要收到项目事实。然后在真实仓库的会话上重跑同样三类评分。这套 29 题说明的是机制，还不能代表一周真实使用的比例。Cursor 的空白对照和属性树两列补采之后，才能写 Cursor 和 Memmy 谁更会用这段记忆。在那之前，能写的是：同一段项目记忆上下文上，Memmy 模型回答 23/29，Cursor 18/29。

可以带去讨论的三句

项目记忆的召回是 22/29，空白对照是 10/29，多出来的题主要是改口和过时。属性树是 11/29，这轮没有超过空白对照。没打开项目的窗口三列都把月报算法讲了出来，这是下一处要修的地方。
