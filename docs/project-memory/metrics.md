## 指标定义

**写入（add）**：评委把最终状态里的每条条目归属为 match / stale / conflict / negative / none，再一对一匹配。`entries.f1` 是决策、经验、进展合在一起的内容 F1。`stateExact` 是必写决策的 content、conflicts、history、user_ids、time 全对的比例。主题用扩展 B-cubed，未匹配的写入稀释精确率，没写出的金标召回为 0。重复主题是一个金标主题被拆成多个；错误合并是一个主题混入多个金标主题。

**检索（search）**：`Recall@k` 是期望主题出现在前 k 个返回主题里的比例。`entryHit` 是期望条目出现在正确位置的比例。

**回答**：`answers.llm` 是裁判判对的比例。`rubric` 是 `mustInclude` 逐字全中的比例。Token F1 按中文字、英文词计算。

**开销**：Add、Search、回答分开。三段都含被测模型（DeepSeek）的调用。裁判（gpt-6-luna）单列，不计入这三段。缓存命中输入、缓存未命中输入、输出分开计数，费用按 `pricing.json`。没有模型调用的段记 0。P95：Add 用任务「受理 → 完成」，Search 用 `search/memory` 请求，回答用阅读模型单次请求。

总表只放效果、费用和时延。按题型的分数、错误类计数和分段 token 写在每条记录里。
