# ADR-0010：桌面项目绑定本机项目记忆

- 日期：2026-11-13
- 状态：已采纳（用户确认实施计划；实现待独立评审）
- 规格出处：v3 §2.2.1–2.2.2、§3.2–3.4、§4.1、§4.8–4.11；Q-03、Q-04、Q-32

## 决定

应用项目内显式开启，默认关闭；本机项目 ID 与 MemOS 返回的 Space ID 一对一绑定，不复用云端协作 ID 或 L3 workspace ID。应用调用 create/space，指定单一领域“通用”，项目背景与规范同步为 instructions。原有 CLI 显式绑定规则保留，桌面会话只认自己的项目绑定，不继承全局环境变量。

后端维护配置目录的 project-memory-bindings.json，采用跨进程锁、原子重命名和失败关闭。Space 创建成功而绑定保存失败时补偿删除新 Space。原始消息、任务 ID、投递状态和用户 ID 在同一受保护文件里作为提交记录持久化；不写进仓库。Agent 只读绑定部分。

实时采集与历史导入都读取本机 Memmy 已保存的 JSONL：仅接收带 webui=true、明确项目 ID 和 websocket 会话键的记录，使用同一轮次转换和原始时间。后台每 3 秒检查变化文件，不等待模型完成；不再从 afterRun 重新生成一套时间。每轮提交键包含 Space、会话键、消息内容和原始时间；先持久化请求，再调用 add/message。网络中断后可重放原请求，整理任务失败由用户显式重试。已有会话仅采集开启之后开始的新轮次；历史通过选择任务导入。取消、没有最终回复、内部续跑和成员协助结果不作为本机用户的新决策采集。

关闭后停止新的采集和召回，已经交给 Memory 的任务仍由原队列处理。重启保留绑定和投递记录，重新开启不自动补采关闭期间的轮次。移除本机项目后解除绑定和本机投递记录，不销毁 Space。主题与来源只读，人工改写/删除不在本轮范围。

应用 BFF 路由是 /api/projects/:projectId/memory 下的绑定、主题、任务、历史导入与重试；受已有 runtime token 保护，由后端确认本机项目归属、会话归属和主题 Space。BFF 通过已有 /api/openmem/v1/* 调用 Memory，不直读记忆表，不增加评测字段。

## 与 release 的兼容

完整合入 upstream/release/v1.2.7；Memory schema 升到 16，兼容原项目记忆 v10 和 release v15。项目记忆任务注册到 release 的模型预算与调度策略，在租约查询、依赖键及并发准入中保留 Space 串行。模型调用仍仅在 M02/M04/M05，检索算法和提示词不变。

## 边界与影响

这是本机体验，不把成员共享会话搬到本地，不实现 PM-24 的云端 Store，也不代表跨成员共享项目记忆。程序崩溃与文件写入失败后的跨服务补偿不是分布式事务：极端情况下创建 Space 后、保存绑定前进程终止可能遗留未绑定空间，后续不按名称自动认领。

## 配置恢复与失败轮次（2026-11-13 补记）

宿主失败回复的 model_error 标记和重启时的中断占位文本不进入项目记忆。MODEL_NOT_CONFIGURED 与 MODEL_CALL_FAILED 一样允许原批次重提为新任务：用户补齐模型配置后可显式重试，不修改原消息/时间以绕过去重。Space/domain 等不可重试原因不变。

投递网络请求不持全局配置锁；每轮最多处理 4 个任务，逐个用持久化 5 分钟租约认领，HTTP 单次最多 60 秒，避免两个后端重复认领同一轮。回写只更新租约 token 仍匹配的任务，不覆盖项目开关。关闭前已经开始的请求可受理并完成，之后不认领新任务。
