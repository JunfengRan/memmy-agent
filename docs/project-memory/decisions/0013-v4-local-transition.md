# ADR-0013：V4 边界重构、本机过渡部署与召回记录退役

- 日期：2026-11-16
- 状态：已采纳（用户确认实施计划）
- 依据：standard V4（2026-11-13 修订）、《项目记忆：代码组织、接口与接入设计》；本轮用户确认优先于旧部署约束。
- 替代：ADR-0008 的召回记录用途，以及此前基于 recall_log 的已告知/复述判断。ADR-0011 的原 UI、本机默认和云端写锁、ADR-0012 的目录绑定与双端接入继续有效。

## 决定

本轮只重构 memmy-agent，不迁移到 MemOS Python 仓库或部署云服务。SQLite、原项目绑定、Space/主题 ID、原始会话、任务与投递 journal 继续使用；这是本机过渡部署，不声明满足 V4 的纯云端部署、Jev 或两段并行调度。其他待决产品规则不自动成为本轮需求。

存储分为 ProjectMemoryStore（主题与条件写）、ProjectPipelineState（消息、任务、上下文、暂缓片段）与 ProjectTaskRuntime（同事务受理/入队）。SQLite 实现原子创建消息/任务和各 Space 队列。模型与向量补齐移到 IndexedProjectMemoryStore，底层 SQLite 只执行索引原语和事务写。纯 ChangeSet 应用在 merge/apply，不再反向依赖 SQLite。

注入渲染、提示词和闭合块剔除的唯一维护源仍在 Memory 项目记忆模块；构建脚本确定性生成 App 与 Backend 资源，--check 检查漂移，两份 hook 仍独立打包。未来 MemOS 模板落地时再更换源头，不在本轮跨仓维护两份实现。

## 无召回记录的写入语义

检索成为无项目记忆写副作用的读取。旧 pm_recall_log 表与历史行保留，但运行时删除日志方法和依赖；不因本次退役改变数据库版本。旧客户端 recall_via 合法值继续接收，不能用于授权。

M02 的 disclosures 引用同会话实际助手消息，用 message_idx/context_idx 与逐字 conclusions 绑定原文；剔除注入后校验，伪造引用、用户消息和不存在的句子不能作为证据。M05 在已归类主题内将这些原话逐项对应到当前决策，记录内容快照；代码校验来源、先后时间与目标；逐字相同的已告知项确定性补全，比较只归一空白、不删除运算符。裁决还要求本轮的明确裁决信号；M05 已绑定 sameAs 但漏标 resolve 时，按该信号和已告知集合确定性绑定，不推断新结论、不覆盖拆分。OCC 冲突后重新读取并判断，不能重放旧目标集合。

内部 resolve/split 增加 processedTargets；生产管线总是显式提供。只把已告知的处理项移入 history；未告知或变化的结论保留。如果原当前结论未被覆盖而要更换，则将其保留为 conflict；split 中未处理冲突留在保留原 ID 的条目上。历史与变更同事务。如果部分告知后的新裁决作者（或无来源拆分的裁决人）仍属于未处理项，直接暂缓为 partial_resolution_membership_conflict，原条目完全保留，避免成员双归属或借裁决删除未告知项；后续上下文补齐后可回填。旧内部 ChangeSet 未带该字段仍按原语义应用，以兼容既有直接存储调用；对外不暴露 ChangeSet。

M02 草稿来源区分 member/adopted/delegated；成员采纳需引用真实、晚于助手回复的用户原话。Agent 未被采纳的决策与库内当前/冲突/历史相同（历史语义匹配通过 history:N 绑定内容快照），在 M05 后的确定性合并中丢弃，不替成员加入已有结论。M02 仍可识别会话内复述。其余经验与轨迹规则不扩展。

## 边界

语义上的同一结论对应仍由现有受约束 LLM 实现，未接入 Jev；原文引用校验不能代替语义判断质量评测。上下文仍使用现有限额，未在上下文窗口内的告知不能授权。跨主题复述不新增全库比较，保持 V4 已注明的局限。旧评测结果不能直接当作新提示词结果。

## 验证

实际命令、结果和质量冒烟见本轮 metrics 及工作项 20261116-project-memory-v4。单测通过不等于纯云端、全部宿主或生产部署已验收。
