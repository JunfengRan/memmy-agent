# ADR-0009：v2.1 评测口径

- 日期：2026-11-11
- 状态：已采纳
- 规格出处：v3 §2.4、§3.6；收回 ADR-0004 里「评委温度必须为 0」对 gpt-6 系列的适用

## 背景

W46–W47 的产品回放没有在数据集 v2.1 上跑完。已有分数混了三件事：数据集是 v2 还是 v2.1、阅读模型是哪一个、开销里有没有算进裁判。`pricing.json` 只有 Claude 单价，DeepSeek 的费用全是 null，表上大量「不适用」。

## 决定

1. 收尾这一轮的实验只用数据集 v2.1（`eval/project-memory/gold-add-memory/dataset/`）。不重跑 v2，不重跑 v0.1（`672919d5`）。旧实现和 main 对照也在 v2.1 上按本口径重跑。
2. 被测模型固定为 `deepseek-v4.1-flash-1017`（`~/.deepseek.env`）。回答也由这个模型生成，阅读提示词仍是产品模板三之后的阅读提示词。Add、Search、回答三段的 token 和费用都算产品开销。
3. 裁判固定为 `~/.openai.env` 里的 `gpt-6-luna`，只走 chat completions，不调用 Decisions 接口。裁判与被测模型不同家族。这个模型不接受温度 0，也不接受 `max_tokens`，请求改用 `max_completion_tokens`，温度为模型默认值，报告里记 null。这是对 ADR-0004「评委温度 0」的一处收回，只适用于不接受该参数的模型。评分缓存键仍含模型和提示词哈希，同一份 run 重评结果不变。
4. 裁判的调用数、token 和费用单列，不计入 Add、Search 或回答。
5. 单价取自官方价格页，写在 `eval/project-memory/gold-add-memory/pricing.json`，注明来源链接和 `fetchedAt`。缓存命中的输入、缓存未命中的输入、输出分开计价。本 ADR 不抄单价。
6. Add 的模型调用按提示词版本拆成抽取（M02）、归属（M04）、判断（M05）。没有模型调用的段记 0，不记 null。测不到才记 null，并写原因。
7. `metrics.md` 只保留本口径下的大版本结果。v1，以及 v2 上用 Claude 阅读或 Claude 裁判的记录，从正文删除。删除前的全文在提交 `47355fa0`。结果相近的重复运行合成一行，写均值和范围。

## 影响

- 总表里没有「相对 v0.1 提升了多少」。能比的是当前版本、旧实现（`9aabf84b`）和 main。
- 阅读上限和只测检索也换成 DeepSeek 作答、gpt-6-luna 裁判，不能和 R-20261110-02～04 的 Claude 上限逐题对比。
- Jev 选题和检索延迟基准不是这三类实验，留在 metrics 的「专项实验」，不重跑。

## 替代方案

- 阅读模型继续用 Claude，回答费用另列。用户要求回答开销计入，且被测模型始终是 DeepSeek，所以回答也用 DeepSeek。
- 费用只报 token、不换算美元。用户要求按官方价格写入 pricing，并保留缓存读、缓存写和输出。
