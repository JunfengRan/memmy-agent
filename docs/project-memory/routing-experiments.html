01两者解决的不是同一层问题

Jev 是 TypeSafe 提供的 System One 决策模型：输入状态与有类型的问题，返回 choice、概率分布等结构化结果。Choice 适合把“这轮属于哪个候选主题”表达成选择题。这个定位来自 TypeSafe 官方介绍，不是本仓库性能实验的结论；本页不采用厂商速度、成本或可靠性宣传作为产品证据。

dsh-superagent 是面向单个 GitHub 仓库的主动编码 Agent 研究原型，建立在 DeepSeek Harness 上：它接收触发消息，由编排者决定新建、续接、忽略或停止工作，再由工作会话执行并交回结果。原型 README 明确它不是官方 DeepSeek 产品，并且公开原型不等同于全部设计方向。项目记忆实验只借用了 dispatch 中的路由规则，没有启动整套 Harness，也没有把执行 Agent 接到 Add 里。

先纠正“用了 Jev”的含义

当前基座的文件和指标沿用了 Jev 命名，但请求实际上由 gpt-6-luna 经 chat completions 生成严格 JSON。它复用了结构化选择题的思路，没有调用 TypeSafe 的 Jev 权重或原生 System One 接口。生成出来的 probabilities 也不能当成已验证校准的 Jev 概率。

阅读顺序：先看基座中的可选选择题，再看独立会话路由比较，最后看 session 直接作为 topic 的端到端实验。这三件事有不同代码、数据集和失败策略。

02基座：在 Add 与 Search 中加入选择题

代码在当前开发分支的 decisions/，由 本分支 ADR-0006 记录，默认关闭。模型只选择，不生成决策正文，不直接提交存储。

Add 的 new 不等于马上创建

通知服务已有“失败重试策略”主题。用户说“这次重试改五次”，选择题可选它；说“新增超时监控”，可选 new；说“回复短一点”，可选 none。这里展示的是协议允许的结果，不是对模型输出的实测预测。

chooseAdd 用本批 query / answer 构造题目，把候选主题做成卡片，选中已有主题后只保留该主题；new 清空候选，再由 M04 判断新建或推迟。none 并不丢弃这轮，它保持原候选继续处理。若指定了多个领域或信息不足，后续仍可能推迟，不能把一个 new 当作越过产品约束的创建命令。

Search 的选中不等于只返回一个主题

chooseSearch 只从确定性召回并排序的主题池中选一个已有 id 或 none。已有 id 被移到候选列表首位；随后仍由当前 MMR、数量和相关度等规则组装输出。none 不清空结果，失败也回到原顺序。它没有替代当前主题内的词面条目门槛，因此不能自动修复第一篇中 q04 的冲突过滤。

请求默认不启用实验。MEMMY_DECISION_TOPIC=1 时才创建决策路由；配置缺失则不启用，调用失败则回退原候选或原排序。测试中还需要 MEMMY_DECISION_TOPIC_IN_TEST=1。模型配置读本地 ~/.openai.env 的 MODEL、OPENAI_API_KEY、OPENAI_API_BASE，文档不包含实际地址和密钥。当前模型请求不传 temperature；“温度零所以确定”不成立。

独立评测的搜索卡只有名称、摘要、描述，不放条目正文；Add 卡含该时刻之前已出现的条目。候选来自金标，绕开了真实抽取、召回遗漏与主题漂移。因此单独选题准，不等于端到端写入和问答准。

03独立会话实验：什么时候允许续接

原型 dispatch 的核心约束是：attach 要有明确指向，主题相近的新请求用 accept 或 ignore，不能仅凭相似度续接。因为错误 attach 会让一个工作项持续接收错误线程的消息；重复开一个工作项往往更容易处理。这是工作编排的代价取舍，移到项目记忆以后也会产生更多小主题。

消息（教学示例）选择题协议允许怎样选Super Agent 协议要求
“失败重试改成五次”且唯一对应已有三次约定选择已有 topic明确修改刚定的内容，可 attach
“另一个通知渠道也要失败重试”可能选择相近 topic 或 new相近的新请求应 accept，不能仅因重试二字 attach
“沿用刚才那个重试策略，补监控”且唯一对应可选择已有 topic明确指向唯一既有工作，可 attach
“回复短一点”none没有工作请求，用 ignore
“停止这个重试改造”没有独立 stop 选项明确指向工作时可 stop

上表是协议差异，不是五条新消息的实测结果。独立路由器会记录人工 stop，停止的 session 不能 attach；数据集没有停止类消息，实际消融没有验证 stop。它也没有 retrieve 动作，因此不要把下面项目记忆实验的 Search 能力归到这个分支。

“Jev + Super Agent”这个旧实验名的实际含义是用 gpt-6-luna 跑 Super Agent 路由提示词。为便于阅读，本页称“Super Agent 协议 × gpt-6-luna”。不存在先调用一个 Jev，再把结果交给另一个 Super Agent 的串联流水线。

04端到端实验：把 session 当作 topic

归档实验 feat/superagent-session-as-topic 基于较早的项目记忆 v0.1。它把 router 分配的 session id 直接当 topic id，锁定后续组织的写入目标。该工作区的同编号 ADR-0006 是分支内决策，不是当前基座选择题 ADR 的补充，也不是其默认实现。

Add：路由决定容器，组织器提炼知识

write 路由一次完成 JSON 决策。accept 创建一个新 topic，attach 只写指定 topic；组织器收到 locked_session，即使输出其他 id，也不会再创建第二个主题。ignore 和 stop 不调用组织，把本轮作为 deferred。此分支的 stop 只停止本轮写入，不把 topic 永久关闭，这与独立会话实验的 stopped 状态不同。

路由卡最多 30 个，按更新时间降序、topic id 作并列排序；每个最多展示 8 条决策正文。指定 domain 时只展示对应领域。这里的“模型没选对”还可能来自卡片截断或上下文不足，不能只评判提示词。

Search：retrieve 是本地实验新增的动作

把问题和已有 session 卡交给同一路由提示词，输出按相关性排序的 topic_ids，可多选，也可以为空。所选主题读取完整条目及 conflicts / history；不再由旧 RRF / MMR 决定选哪些主题，也没有默认路径的词面条目裁剪。relativity 按路由次序从 1 线性降到 0，再受 memory_limit_number 和 relativity 门槛约束；这是顺序映射，不是模型置信度。

召回日志仍记录返回的决策，供后续“已告知”使用。模型缺配置或路由解析失败时，项目检索抛 STORE_UNAVAILABLE，不回退词法；这和基座中可选选择题的回退策略不同。路由每次是一次 completeJson，温度 0，没有原型中的多轮查票与工具执行循环。

实验与默认路径的边界

选哪些主题由模型决定，违反默认检索的确定性约束；未知目标的处理也有分支特例。它只能作为显式实验理解，不能未经设计决策替换当前基座。温度 0 不保证重复运行相同。

05三组结果分别说明什么

一、金标主题卡上的选择题

专项 R-20261106-01（当前 metrics 的专项实验）：数据集 v2；Add 34 题，Search 23 题；模型 gpt-6-luna，单次专项结果，不是多次均值。Add 归属 30/34=0.882，已有主题 21/21、新建 3/5、无关 6/8。Search 选中 Recall@1 为 19/23=0.826，同卡片词法基线 0.522。候选来自金标，不能证明产品抽取或实际召回达到了这个水平。

二、23 条消息的会话归属消融

6 个 Cursor 原始会话交错成 23 条消息；每个模型格子跑 3 次，词法基线 1 次。下表是均值。金标按来源会话，不是人工判定“同一工作”；同一会话里可能包含新请求。

这批小样本中，Super Agent 协议在两个模型下都获得更高纯度，提示协议可能是重要因素；不能据此宣称纯度完全由协议决定。两种协议的卡片内容也不完全一致。B³ F1 只是在精确与召回之间折中，0.62–0.67 相近不代表行为相同。仅 3 次运行不能支持普遍优劣或统计显著性的结论。原始预测和范围见 消融说明。
